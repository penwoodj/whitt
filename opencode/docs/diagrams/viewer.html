Whitt Architecture Diagrams

4-project system architecture • Version 1.0 • ~/code/whitt/opencode/docs/diagrams/

00 - System Overview

100%
Whitt (UI/TUI)
agent-queue (Scheduling)
yaml-to-rust-agentsdk (Execution)
model-router (Model Selection)

Key Points

  • Whitt is the user-facing shell - it displays, it doesn't execute
  • agent-queue orchestrates scheduling - it delegates execution to yaml-to-rust-agentsdk
  • yaml-to-rust-agentsdk is the execution engine - it runs workflows and calls LLMs
  • model-router selects the best model for each task (future integration)
  • All communication is CLI subprocess (JSON stdin/stdout) in MVP

01 - Whitt MVP Architecture

100%

Data Flow

  • User types prompt in Chat UI
  • Whitt calls yaml-to-rust-agentsdk CLI to compile prompt → YAML workflow
  • Compiled workflow enqueued via agent-queue CLI
  • agent-queue dispatches to yaml-to-rust-agentsdk CLI for execution
  • Results stream back through queue state → Whitt UI updates

02 - Communication Protocols

100%

Protocol Details

  • All protocols use CLI subprocess invocation (stdin/stdout JSON)
  • No HTTP, no REST, no WebSocket, no gRPC in MVP
  • Post-MVP: Rust library API (direct function calls via Cargo dependency)

03 - Queue Integration

100%

State Machine

  • 10 states: NEW → QUEUED → SCHEDULED → LEASED → RUNNING → DONE/FAILED/DLQ/CANCELED/EXPIRED
  • Lease protocol: 60s TTL, 15s heartbeat
  • Retry: max 3 attempts with exponential backoff (1s → 2s → 4s)
  • Whitt displays state but does NOT manage transitions

04 - Future P2P Gamified Compute Sharing

100%

P2P Vision

  • Share useful workflows → earn compute credits
  • Proof-of-satisfaction verifies quality before credits awarded
  • No mandatory idle-time compute contribution required
  • Phase D (far future) - build stable MVP first

05 - Feature Ownership / Scope Boundaries

100%

Ownership Rules

  • Each feature has exactly ONE owner (or shared with clear boundaries)
  • Whitt = display and interaction only, NO execution logic
  • agent-queue = scheduling and state only, NO execution logic
  • yaml-to-rust-agentsdk = execution only, NO UI, NO scheduling
  • model-router = model selection only, NO execution, NO UI
